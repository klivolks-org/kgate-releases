kGate is a self-hosted API Gateway and Messenger. One binary, your infrastructure, no dependency on our servers to keep running.

Pull and run
# pulls the image and starts kGate on port 8080
docker pull ghcr.io/klivolks-org/kgate:latest
docker run -d --name kgate --restart=always \
  -v kgate-data:/app/data \
  -p 8080:8080 \
  ghcr.io/klivolks-org/kgate:latest

Then open http://localhost:8080/install to finish setup. kGate won't configure a reverse proxy for you — put nginx, Apache, or your platform's ingress in front of it for TLS.

Add the repository, then install
# adds kGate's signed apt repository
curl -fsSL https://klivolks-org.github.io/kgate-releases/kgate-archive-keyring.gpg.asc | sudo gpg --dearmor -o /usr/share/keyrings/kgate.gpg
echo "deb [signed-by=/usr/share/keyrings/kgate.gpg] https://klivolks-org.github.io/kgate-releases/apt stable main" | sudo tee /etc/apt/sources.list.d/kgate.list

# installs and starts kGate
sudo apt-get update && sudo apt-get install kgate
sudo systemctl enable --now kgate

Future releases arrive through apt-get upgrade, same as any other package. Setup continues at http://localhost:8080/install.

Add the repository, then install
# adds kGate's signed yum repository
sudo tee /etc/yum.repos.d/kgate.repo <<EOF
[kgate]
name=kGate
baseurl=https://klivolks-org.github.io/kgate-releases/yum
enabled=1
gpgcheck=1
gpgkey=https://klivolks-org.github.io/kgate-releases/kgate-archive-keyring.gpg.asc
EOF

# installs and starts kGate
sudo dnf install kgate
sudo systemctl enable --now kgate

Works with dnf or yum. Setup continues at http://localhost:8080/install.

Download and run the installer
// download the latest installer, then run it as Administrator
kgate-setup.exe

Download kgate-setup.exe — it registers kGate as a Windows service and can optionally configure an IIS reverse-proxy site for you during setup.

Gateway

Request routing, service registry, and referer-based access control for every API behind it.

Messenger

WebSocket pub/sub with delivery tracking and signed webhook fallback for offline subscribers.

Runs offline

No CDN dependencies, no phoning home to operate. Install it on an air-gapped network and it works.

What happens after install

Same four steps, every platform

Package managers and installers differ, but every install lands you in the same setup wizard.

01

Choose components

Run Gateway, Messenger, or both from the same install.

02

Pick a database

MongoDB, MySQL, SQL Server, or the built-in embedded store — no external dependency required.

03

Create your admin account

Only asked for on a fresh database — existing installs keep their existing accounts.

04

Activate

Start a 30-day trial, enter a license key, or request offline activation.

Licensing works offline too

Every license is a cryptographically signed token, verified locally — editing the license file can't extend it. If your kGate instance has no internet access, its admin panel shows an Installation ID you can send us for a signed token you paste back in, with no network call required on your end.
